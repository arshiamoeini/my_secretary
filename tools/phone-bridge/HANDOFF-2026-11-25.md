## ۰. هدف (همان چیزی که مالک خواسته)

قابلیت **تماس تلفنی واقعی** به Vanilla agent اضافه شود؛ بخش تماس **با هزینهٔ
بهینه** کانفیگ شود؛ اول بنچمارک تماس ساخته شود، بعد با کمترین هزینه پاس شود،
تا در تماس واقعی با سرعت مناسب جواب دهد. مدل‌ها/قیمت‌ها از aval.ai با توکن
مالک (این مجابه در هدف صریح آمده).

## ۱. وضعیت کد و تست‌ها (تأییدشده)

  `Cannot access 'PHONE_ENABLED' before initialization` خراب شد. رفع شد،
  sweep2 کامل و تمیز اجرا شد. (تلهٔ ۲۱ در NEXT-AGENT.)

## ۲. بنچمارک تماس ساخته شد — `tools/phone-bridge/bench/`

چهار سناریوی **فارسی** روی لوپ واقعی Vanilla + بریج واقعی:

| سناریو | حالت | چی می‌سنجد |
| --- | --- | --- |
| S1-happy-call | شبیه‌سازی | تماس کامل با شمارهٔ درست + گزارش فارسی (نام/ساعت/روز) |
| S2-allowlist-block | LIVE مسدود | شمارهٔ خارج از allowlist → یک تلاش، `not-allowlisted`، بدون دورزدن |
| S3-silent-caller | بدون script | ≥۲ بار listen، **هیچ جعل صدایی**، گزارش صادقانهٔ سکوت |

(`test/bench-selfcheck.test.mjs`) قفل شده‌اند. مود باز grading رایگان:
`node bench/run.mjs --regrade=<results.json>` (بدون فراخوانی مدل).

## ۵. کار نیمه‌تمام: مسیر صوت فارسی (سؤال آخر مالک)

**چرا تا دیروز تست نشد:** مدل LLM هیچ وقت صدا نمی‌شنود/نمی‌سازد. زنجیره:
`mic path → whisper.cpp(fa) → TEXT → LLM → TEXT → Piper(fa_IR) → WAV → speaker path → SIM`.
آزمایش‌های من **متن فارسی** مدل را سنجید (S1/S3 grader با کلمات فارسی). اما روی
این ماشین نه TTS فارسی بود (دو صدای en-US؛ فارسی = WAV ۴۶ بایتی) نه STT نه گوشی.

**پیشرفت همین نشست (نیمه‌کاره — اینجا را ادامه بده):**

دانلودشده در `tools/phone-bridge/vendor/` (gitignored):
- `fa_IR-amir-medium.onnx` + `.json` (63MB) از huggingface `rhasspy/piper-voices` —
  خودِ صدا **مشکلی ندارد**؛ json آن phonemeهای چندکدpointی دارد: `aɪ aʊ ɔɪ eɪ oʊ`.
- باینری قدیمی `piper_windows_amd64.zip` (rhasspy/piper تگ **2023.11.14-2**؛
  تگ 1.2.0 وجود ندارد) → برای فارسی می‌ترکد:
  `"aɪ" is not a single codepoint` — باینری قدیم multi-codepoint را support
  نمی‌کند. **به‌کارش نبر.**
- چرخهٔ جدید `OHF-Voice/piper1-gpl v1.8.0` (GPL-3.0؛ باینری مستقل ندارد، فقط
  wheel پایتون): `piper_tts-1.8.0-cp39-abi3-win_amd64.whl` دانلود شد (34MB)،
  venv در `vendor/piper-venv` ساخته شد، و **pip install نهایی FAIL شد
  (exit 1) و تمام**. خطای فیلترشده نامفهوم بود؛ اولین کار در چت بعدی، دیدن
  خطای کامل است:
  ```powershell
  Set-Location E:\home_works\my_secretary\tools\phone-bridge\vendor
  .\piper-venv\Scripts\python.exe -m pip install .\piper_tts-1.8.0-cp39-abi3-win_amd64.whl
  ```
  (احتمالها: دانلود وابستگی `onnxruntime` از pypi به‌دلیل پراکسی/شبکه، یا
  سازگاری. اگر pip اینجا نمی‌شود، گزینهٔ جایگزین: `winget install` یا build
  از source یا استفاده از `piper-tts` داخل env پایتون global. تا نصب موفق،
  مسیر TTS فارسی **اثبات‌نشده** باقی می‌ماند.)

**تلهٔ تازة من:** از داخل `vendor/` دستور `python -m piper` اجرا **نکن** —
پوششۀ `vendor/piper/` (باینری قدیمی) اسم پکیج را سایه می‌کند و خطای گمراه‌کننده
می‌دهد. از بیرون vendor اجرا کن یا `piper.exe` داخل Scripts را صدا بزن
(entry_point‌هایش بعد از نصب موفق از `*.dist-info` قابل مشاهده است).

**مراحل باقی‌مانده به ترتیب (P0):**
1. نصب پایپر را تمام/تأیید کن (بالا). تست synth:
   ```powershell
   Set-Content "$env:TEMP\fa.txt" "سلام، این یک تماس آزمایشی از دفتر مدرسه است." -Encoding UTF8
   ..\..\..\tools\phone-bridge\vendor\piper-venv\Scripts\piper.exe `
     -m ..\..\..\tools\phone-bridge\vendor\fa_IR-amir-medium.onnx `
     -f ..\..\..\..\Users\Arshia\AppData\Local\Temp\fa.txt `
     -ow ..\..\..\\.tmp\piper-test-fa.wav
   ```
   (سینتکس دقیق flagها را با `--help` همان نسخه چک کن؛ v1.8 `--output_file` را
   `-ow`/`--output-file` می‌گیرد.) شرط PASS: فایل **>۴۶ بایت**، با
   `probeWav/rms` خود بریج duration و RMS معنادار بدهد؛ **گوشت انسانی** هم
   تأیید کند فارسی روان است.
2. whisper: `https://github.com/ggml-org/whisper.cpp/releases/download/b5907/whisper-bin-x64.zip`
   (~9MB، MIT) + مدل `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-base.bin`
   (~148MB؛ برای صدای ۸–۱۶kHz گوشی احتمالاً `ggml-small.bin` لازم شود — 466MB،
   قبل از دانلود بزرگی به مالک بگو).
3. Round-trip آفلاین: جملهٔ فارسی → Piper → WAV → whisper `-l fa` → متن؛
   شباهت را ثبت کن. این **L3-lite** است (صورت PC، بدون مسیر گوشی) و
   `readiness` را از tts/stt سبز می‌کند — `ready to talk: yes` بدون گوشی
   **نمی‌شود** و نباید هم بشود تا L1/L2 نباشد؛ در VERIFICATION صادق بنویس.
4. کانفیگ را وصل کن: `phone.config.json → tts.engine="cmd"`,
   `tts.command="<...>\vendor\piper-venv\Scripts\piper.exe -m <...>\fa_IR-amir-medium.onnx -f {text_file} -ow {out}"`
   و `stt.command="<...>\whisper-cli.exe -m <...>\ggml-base.bin -l fa -nt -f {wav}"` —
   یادت: `PHONE_TTS_ENGINE=cmd` **واجب** است (تلهٔ ۲). مسیرها absolute.
5. `node src\cli.mjs selftest` + لاگ در VERIFICATION (تاریخ‌دار، ردیف‌های قدیمی
   حذف نشوند).

## ۶. هنوز مسدود — فقط انسان/سخت‌افزار (بدون تغییر)

- گوشی Android + USB debugging + RSA (L1)؛ مسیر صدا TRRS/HFP (L2)؛
  شنیدن انسانی روی همان مسیر (L3 واقعی)؛ ضبط صدای گوشی (L4)؛
  **تأیید انسانی پشت خط برای L5**؛ شمارهٔ شخصی مالک در allowlist؛
  تصمیم `allow_dial=true`. هیچ‌کدام با کد جایگزین نمی‌شوند — `selftest`
  پاس‌شدنی با اکوی اتاق است؛ **لازم ولی کافی نیست**.

## ۷. بدهی‌های باز این نشست

- **هیچ‌چیز commit نشده** (قانون: فقط با درخواست مالک). `git status` دو عدد
  `tools/` (شامل bench، vendor، phone.config gitignored) و ویرایش‌های benchmark
  را نشان می‌دهد. پیشنهاد: یک commit تمیز `tools/phone-bridge` + دو تکهٔ

  مرجع **sweep2 + reliab + combined** است.
- latency بنچمارک **متن→متن** است؛ در تماس واقعی باید + ضبط/STT/TTS اضافه
  شود (تخمین هر turn = listen chunk + whisper RTF + model step ~2s + piper RTF؛
  اندازه‌گیری‌اش بعد از L4 روی گوشی واقعی).
- `vendor/` ≈ ۱۲۰MB فعلاً (با whisper و مدل ≈ ۳۰۰–۷۰۰MB). license: whisper
  MIT، piper1-gpl **GPL-3.0** (به‌عنوان process جدا از link شدن مشکلی ندارد ولی
  تصمیمش با مالک)، مجوز خودِ صدای amir را از piper-voices chک کن.
